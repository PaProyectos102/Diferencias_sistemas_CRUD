Paradigma Declarativo de Grafo

¿De qué trata GraphQL y para qué se usa?

GraphQL es un lenguaje de consulta para APIs y un motor de ejecución del lado del servidor desarrollado internamente por Facebook (Meta) en 2012 y liberado como código abierto en 2015. Permite a los clientes solicitar exactamente la estructura y campos necesarios, recibiendo una respuesta JSON con la forma idéntica a la pedida.

GQL

🎯 ¿Para qué se usa principalmente?

1. Patrón BFF (Backend-For-Frontend)

Ideal como capa intermedia entre múltiples microservicios de backend y las interfaces de usuario (web y móvil), agregando datos dispersos en una única respuesta coherente.

2. Aplicaciones Móviles y Redes Lentas

Reduce drásticamente el consumo de batería y datos móviles al evitar el tráfico de propiedades innecesarias y resolver pantallas completas en un único round-trip.

3. Vistas Complejas y Heterogéneas

Pantallas como feeds de redes sociales, dashboards analíticos o perfiles de usuario que combinan decenas de entidades interrelacionadas.

🏛️ Principios Arquitectónicos Fundamentales

1. Endpoint Único

A diferencia de REST (que expone cientos de URIs), GraphQL canaliza todas las consultas y mutaciones hacia un único punto de entrada: típicamente POST /graphql.

2. Consultas Declarativas (Queries y Mutations)

El cliente redacta un documento declarativo indicando exactamente qué propiedades quiere recibir. Si pide { usuario { nombre } }, el servidor devolverá únicamente el nombre sin ningún campo extra.

3. Esquema Fuertemente Tipado (Schema SDL)

El servidor expone un contrato formal definido en SDL (Schema Definition Language) con tipos escalares (String, Int, Boolean, ID) y tipos de objeto. El cliente puede validar su consulta antes de enviarla.

4. Resolvers Desacoplados

Cada campo en el esquema está respaldado por una función resolutoria (*resolver*). El resolver de un campo puede consultar una base de datos SQL, otro llamar a una API externa y otro a una caché Redis de forma transparente.

✅ Ventajas Técnicas

  • Cero Over-fetching: El cliente nunca recibe atributos no solicitados.
  • Cero Under-fetching: Resuelve grafos de relaciones en una sola petición HTTP.
  • Autodocumentación Nativa: Herramientas como GraphiQL y Apollo Studio permiten introspección en vivo.
  • Autonomía en Front-End: Los desarrolladores de UI modifican sus pantallas sin esperar nuevos endpoints en el backend.

⚠️ Limitaciones Arquitectónicas

  • Caché Compleja en Red: Al enviar peticiones POST a un único endpoint, se anula la caché HTTP estándar de navegadores y CDNs.
  • Sobrecarga en Base de Datos: Consultas anidadas pueden provocar el problema N+1 si no se usan librerías como DataLoader para batching de peticiones.
  • Vulnerabilidad a DoS Semántico: Consultas recursivas maliciosas pueden colapsar la CPU del backend si no se implementa análisis de costo de consultas.
Implementación de Código

💻 ¿Cómo se codearía una API GraphQL para que funcione?

A continuación se muestra el código real y completo para implementar este servicio tanto en el Backend (Schema y Resolvers) como en el Frontend (Cliente Web):

Paso 1: Definir el Esquema Fuertemente Tipado (Schema SDL) GraphQL Schema 
# Definición de tipos de datos del dominio
type Usuario {
  id: ID!
  nombre: String!
  rol: String!
}

type AuthPayload {
  token: String!
  user: Usuario!
}

# Operaciones de Lectura
type Query {
  obtenerUsuario(id: ID!): Usuario
}

# Operaciones de Escritura / Mutación
type Mutation {
  login(usuario: String!, password: String!): AuthPayload
}
Paso 2: Implementar los Resolvers y Servidor en Backend (Node.js / Apollo) Server Implementation 
import { ApolloServer } from '@apollo/server';
import { startStandaloneServer } from '@apollo/server/standalone';

// Mapeo de resolvers a funciones concretas
const resolvers = {
  Query: {
    obtenerUsuario: (_, { id }) => ({ id, nombre: "Juan Perez", rol: "DEV_LEAD" })
  },
  Mutation: {
    login: (_, { usuario, password }) => {
      if (usuario === "admin" && password === "123456") {
        return {
          token: f"jwt.gql.${usuario}.valid",
          user: { id: "1", nombre: "Administrador Principal", rol: "ADMIN" }
        };
      }
      throw new Error("Credenciales invalidas");
    }
  }
};

const server = new ApolloServer({ typeDefs, resolvers });
const { url } = await startStandaloneServer(server, { listen: { port: 4000 } });
console.log(`Servidor GraphQL listo en: ${url}`);
Paso 3: Consumir la API desde el Frontend (JavaScript / Fetch) Client Implementation 
async function autenticarUsuarioGraphQL(usuario, password) {
  const mutationQuery = `
    mutation LoginUser($u: String!, $p: String!) {
      login(usuario: $u, password: $p) {
        token
        user {
          id
          nombre
        }
      }
    }
  `;

  try {
    const response = await fetch('/graphql', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({
        query: mutationQuery,
        variables: { u: usuario, p: password }
      })
    });

    const result = await response.json();
    if (result.errors) {
      throw new Error(result.errors[0].message);
    }

    const { token, user } = result.data.login;
    console.log('Login GraphQL exitoso:', user.nombre);
    return { token, user };
  } catch (err) {
    console.error('Fallo la consulta GraphQL:', err.message);
  }
}
